# Idle memory investigation (2026-10-13)

The reported symptom was approximately 300 MB in btop on macOS using the same
configuration as this Windows machine. No macOS machine was available for this
investigation. The changes below address reproduced unnecessary retention;
their effect on that macOS RSS value still needs measurement.

## Findings and changes

- A fresh native terminal with empty history uses about 2–3 MB of Rust heap for
  the tested 80×24 through 200×60 grids. This includes vte's 2 MiB synchronized
  update reserve. History grows on demand; the 10,000-line setting does not
  allocate a complete history at startup. Filled history does add tens of MB,
  depending on columns. PTY output is bounded and images start empty.
- In locked cosmic-text 0.19, the generic `Family::Monospace` fallback probes
  every installed monospaced face when `monospace_fallback` is disabled, as in
  this dependency graph. The renderer now resolves the generic primary family
  to an installed name before shaping. On this font-heavy Windows installation,
  shaping ASCII `0` previously retained 729 font files (about 3.14 GB of mapped
  source data); the named equivalent retained two files (about 1.50 MB), with
  the same font, glyph and advance. **Mapped source length is not RSS.**
- Configured fallbacks previously replaced the platform's script-specific
  fallbacks. They now precede them. Japanese locales such as `ja-JP` select
  Japanese CJK candidates before the common/general scan. This reduces
  unnecessary font probes while retaining the configured priority and terminal
  grid. The configured JetBrainsMono/Hack fonts already avoid the generic
  monospace issue; its measured reduction must not be attributed to that config.
- The actual config registers 463 themes. The old validation compiled about
  15,000 small Ruby expressions to transfer their names and colors, including
  after status-bar callbacks. Temporary compiler objects made a substantial
  contribution to memory. One sequential transfer replaces the per-field
  compilations, followed by owner-thread GC after loading and completed requests,
  including callback/validation failures after rollback. Registered themes,
  callbacks, mutable theme values and `GC.disable` remain covered by regression
  tests.
- Both wallpapers are about 25.17 MB decoded. The landscape image retains
  about 2.50 MB of compressed CPU pixels and one full-resolution GPU texture.
  Existing lossless compression and bounded upload behavior are preserved.

`TOYOTERM_LOG=warn,toyoterm::soak=trace` records installed font faces, retained
font sources and their unique byte lengths alongside existing resource counts.
These describe application references, not driver memory or physical residency.
The inventory is only collected when that trace target is enabled.

## Windows evidence

Windows 11 build 26300, NVIDIA GeForce RTX 4070 Ti SUPER, DX12,
`Bgra8UnormSrgb`, 960×600 physical surface, bundled external ConPTY. Release
builds use locked dependencies. Baseline commit:
`238f9c70170235aeb2da16c102e8febc50766dfb`; baseline binary SHA-256:
`735955faf924b1b81bec81990ea58e9288211368f052ddc2caa845355d7f5f07`.

Each case uses two fresh processes, a 30-second run sampled once per second,
and the median of the last ten samples. The GUI PID excludes the shell and
measurement process. Config copies, required Ruby files and both wallpapers are
hashed and retained. The personal case uses JetBrainsMono Nerd Font 20,
Hack Nerd Font fallback, opacity 0.95, wallpaper opacity 0.25 and the complete
theme/widget config. The minimal cases differ only in generic `monospace`
versus explicit `Consolas`.

Before the change, the causal generic/explicit comparison was:

| Font selection | Idle working set, runs 1 / 2 (MiB) | Private commitment, runs 1 / 2 (MiB) |
| --- | --- | --- |
| Generic monospace | 151.94 / 150.83 | 151.74 / 150.60 |
| Explicit Consolas | 119.53 / 119.09 | 131.92 / 130.99 |

The personal baseline was 159.81 / 156.79 MiB working set and
198.45 / 196.23 MiB private commitment. These metrics exclude GPU memory;
do not compare private commitment directly with macOS RSS.

The controlled comparison with the changed implementation was:

| Setting / metric (MiB) | Before, runs 1 / 2 | After, runs 1 / 2 |
| --- | --- | --- |
| Minimal: working set | 151.94 / 150.83 | 120.25 / 119.02 |
| Minimal: private commitment | 151.74 / 150.60 | 130.86 / 131.70 |
| Personal: working set | 159.81 / 156.79 | 131.32 / 130.31 |
| Personal: private commitment | 198.45 / 196.23 | 165.10 / 163.62 |
| Personal: private working set | 104.44 / 102.37 | 75.96 / 75.85 |

Personal working set decreased by 26.48–28.49 MiB (16.9–17.8%). Its sampled
startup working-set maximum was 243.29 / 201.83 → 146.60 / 145.76 MiB.
One-second samples can miss a peak; these are observed maxima, not exact peaks.
All comparison runs exited successfully with no GUI ERROR records. There were
no builds or tests during sampling. The measured after binary SHA-256 was
`f9158656c177c15786359cb26a4db692e3749ca48e8550173b8c52b5fb2ae25f`.

A final confirmation also covers uncommon/variable font weight regression
handling and GC on failed-request rollback. It uses the same personal config
with final binary SHA-256
`14cd9d90c1455fd7f876fd4bd5ded3d19d1c4879ee324cc41dd37ed41fd20d7f`:
131.20 MiB idle working set, 165.08 MiB private commitment and 75.81 MiB private
working set. It exited successfully with no GUI ERROR records.

Direct GC timing on the current debug build (200 samples after five warmups)
was about 0.035 ms for an empty config and 0.736 ms for the personal config,
after subtracting median `nil` eval overhead. This is a diagnostic cost estimate,
not a before/after callback latency result or a release performance measurement.

Raw evidence is retained locally under
`.soak-results/memory-20261013-baseline*`, `memory-20261013-after`,
`memory-20261013-final-confirmation`, `memory-20261013-fonts` and
`memory-20261013-script`, including frozen comparison binaries and their
ConPTY sidecars. Measurements are diagnostic observations, not universal memory
thresholds or a macOS performance claim.

## Validation

The final code passed `cargo fmt --check`, the crate architecture checker,
`cargo clippy --workspace --all-targets --locked -- -D warnings`,
`cargo test --workspace --all-targets --locked`, and the license checker.
The soak/performance Python contract suites passed 10 / 6 tests. A real GUI run
also exercised the new custom-config idle option.

The final release binary passed `gui-smoke-test` on Windows; the font trace
recorded two retained font files at cell-width measurement and three after pane
update, out of 2,663 installed faces. The four opt-in `gpu_` renderer tests passed
on the available GPU, covering wallpaper alpha, terminal image blending,
inactive-window transparency and Unicode bitmap composition. No stored render
snapshots were refreshed. The separate transparent-cell replacement GPU test
also passed. macOS/Metal, Linux, interactive IME/glyph inspection
and long idle/soak remain outstanding.

## Reproduce on macOS

Build release binaries for the original and changed code and keep their paths
separate. Run the same configuration, required libraries, font versions, shell
profile, display scale and window geometry with both binaries:

```sh
python3 scripts/soak-test.py gui --executable /absolute/path/toyoterm-before \
  --scenario idle --config "$HOME/.config/toyoterm/config.rb" \
  --idle-seconds 60 --interval 1 --warmup 10 \
  --output .soak-results/macos-memory-before
python3 scripts/soak-test.py gui --executable /absolute/path/toyoterm-after \
  --scenario idle --config "$HOME/.config/toyoterm/config.rb" \
  --idle-seconds 60 --interval 1 --warmup 10 \
  --output .soak-results/macos-memory-after
```

Repeat with new output directories. Use the printed GUI PID to correlate btop
and `ps -o pid,rss,vsz -p GUI_PID`; macOS btop uses process resident size, while
tree aggregation can include child processes. Save `vmmap -summary GUI_PID` and
`footprint -p GUI_PID` separately to distinguish font mappings, malloc and
Metal/IOKit contributions. These are different metrics. The
[btop macOS collector](https://github.com/aristocratos/btop/blob/main/src/osx/btop_collect.cpp)
reads `pti_resident_size` for process memory.

Compare warmed idle RSS and startup spikes. Inspect retained-font trace counts
after Japanese, emoji and Nerd Font symbols are displayed. Also inspect the
actual glyphs, fixed cell alignment, wallpaper/transparency, reload and resize
on macOS; Windows and headless tests cannot validate Metal or Retina rendering.
