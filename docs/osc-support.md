# OSC support

This page tracks Operating System Command (OSC) support in toyoterm. The audit
covers the sequences recognized by the current `alacritty_terminal` 0.26 / VTE
0.15 backend plus common shell and terminal extensions. It does not promise
support for every vendor-private OSC number.

Both BEL and ST termination are accepted unless a row says otherwise.

## Supported

| OSC | Support |
| --- | --- |
| 0, 2 | Set or reset the pane/window title. |
| 1 | Store a bounded icon title independently as pane metadata. It is available to trusted Ruby as `Pane#icon_title` and through OSC 1337 `ReportVariable=session.terminalIconName`; toyoterm has no separate visual icon-title surface. |
| 4, 104 | Set, query, and reset indexed palette colors. Queries reflect the configured ANSI palette, the xterm 256-color palette, and OSC overrides. iTerm2's OSC 4 `-1` and `-2` query aliases report the active default foreground and background, including OSC overrides. |
| 5, 105, 106 | Set, query, reset, enable, and disable xterm bold, underline, blink, reverse, and italic special colors, including the OSC 6 mode-control alias and ANSI-color override mode. These colors are applied to the corresponding SGR cell attributes, including slow and rapid blink, and the bounded color stack preserves the settings. |
| 6 | Set the active pane's tab background from iTerm2 red/green/blue brightness components and reset it (together with the title) using `1;bg;*;default`. The override is rendered after all three components have arrived. |
| 7 | Report the working directory with a `file://` URI. |
| 8 | Attach hyperlinks to terminal cells. |
| 9, 777 | Show bounded, rate-limited desktop notifications when `behavior.allow_osc_notifications` is explicitly enabled. OSC `9;4` progress states are independent of that permission and annotate the reporting pane's tab title with normal, error, indeterminate, or paused/warning progress. Error may omit its percentage; paused/warning may omit it to retain the current percentage. Supplied values outside 0–100 are ignored. |
| 99 | Show OSC 99 title/body notifications, including ID-based chunks and padded or unpadded base64 payloads, answer capability queries, and report the bounded set of accepted identified notifications through `p=alive` polling (positive expiry deadlines are removed before replying). `always`, `unfocused`, and `invisible` occasions, urgency levels 0–2, and every standard sound (`system`, `silent`, `error`, `warn`/`warning`, `info`, and `question`) are honored on every desktop platform through native mappings. The eight universally defined `n=` icon names are resolved through the Linux icon theme or bounded built-in 48×48 RGBA fallbacks on other desktops; other safe application icon names remain available to Linux themes. Transmitted `p=icon` PNG/JPEG/GIF data is decoded into a bounded 16-entry `g=` cache and delivered through temporary PNGs on every desktop platform; input is limited to 1 MiB and 512×512 pixels. Up to three `p=buttons` labels of 128 UTF-8 bytes each are forwarded to the desktop notification backend. Linux, macOS, and Windows advertise `a=report`, `c=1`, and `w=1`; return activation/button/close responses to the originating pane; enforce positive auto-expiry and explicit close; and bound tracked notifications and concurrent response listeners at 128. Reusing an ID explicitly closes the tracked notification before showing its replacement and suppresses the obsolete notification's close report. The macOS listener has an explicit cancellation path so replacement, expiry, eviction, and shutdown do not strand response waits. Uses the same opt-in, bounds, and rate limit as OSC 9/777. |
| 10, 11, 12 | Set, query, and reset foreground, background, and cursor colors (resets use OSC 110, 111, and 112). Queries reflect the active toyoterm theme and OSC overrides. |
| 13–16, 18, 113–116, 118 | Set, query, and reset xterm pointer foreground/background and Tektronix foreground/background/cursor colors. Successive parameters beginning at OSC 13 can also set or query OSC 17/19 selection colors. Pointer/Tektronix values are retained for protocol-compatible round trips and by the bounded color stack; toyoterm has no Tektronix display and native desktop cursor themes do not expose recoloring. Resets fall back to the active foreground, background, or cursor theme color. |
| 17, 19, 117, 119 | Set, query, and reset xterm selection background and foreground colors. Explicit colors override the configured selection rendering; resets restore it. Queries use the configured selection background or foreground as the legacy protocol fallback when the corresponding color is dynamic. |
| 21, 30001, 30101 | Set, query, and reset the 256-color palette plus foreground, background, cursor, cursor-text, selection, visual-bell, and `transparent_background_color1` through `transparent_background_color7` colors with Kitty's unified color control. Hex, `rgb:`, `rgbi:`, alpha-suffixed values, and common basic color names are accepted. Empty values select the specified dynamic behavior: cursor uses foreground, cursor-text uses background, selection colors reverse each cell, visual-bell chooses a contrasting color before BEL flashes the pane for 150 ms, and transparent slots become unset. Transparent slots apply their clipped 0–1 alpha to matching cell backgrounds and inherit `window.opacity` when alpha is omitted or negative; wallpaper remains visible beneath matching cells. Alpha suffixes on opaque fields are accepted but ignored. Bare keys restore defaults and queries return an empty value for dynamic or unset state. Foreground/background have no dynamic form and ANSI palette entries reject empty assignments as specified. Push/pop preserves all supported fields on a bounded 10-entry stack. |
| 22 | Set, reset, push, pop, and query the mouse-pointer shape using the 30 specified CSS names. Each screen has a bounded 32-entry stack, reset with terminal state; the active shape applies while the pointer is over that pane. |
| 50 | Set and query a bounded UTF-8 font family, select the configured primary/fallback families through xterm absolute or relative `#` menu indices, and report the active family or menu position. Changes rebuild text shaping, recalculate cell width, and resize pane PTYs. The iTerm2 `CursorShape=` extension sets the text cursor shape independently. |
| 52 | Copy UTF-8 text to the system clipboard when `behavior.allow_osc52_copy` is explicitly enabled. Reads stay disabled and decoded payloads are limited to 64 KiB. |
| 66 | Render bounded Kitty text-sizing blocks with explicit or Unicode-derived widths, integer scales 1–7, fractional numerator/denominator scaling, and top/bottom/center plus left/right/center alignment. Blocks occupy and advance by their declared cell rectangle, wrap atomically, follow scrollback, and render a cursor spanning the occupied rectangle. Combining characters extend the preceding block; normal and sized text skip lower rows and erase top-row intersections according to the protocol; ICH/DCH/IL/DL preserve, shift, or erase whole blocks at split and clipping boundaries; and mixed normal/multicell selections extract each logical text block once. Payload text is limited to 4 KiB and malformed metadata is ignored. Resizing discards blocks when their cell mapping cannot be preserved, as permitted when a block no longer fits. |
| 133 | Prompt start (`A`), command-line start (`B`), command start (`C`), and command finish (`D[;status]`) markers. Up to 4,096 bounded markers follow scrollback movement; completed command-output zones receive a margin marker colored by exit status, `previous_prompt` / `next_prompt` navigate prompts, and command-output actions select the latest block or cycle through all retained complete `C`–`D` blocks. Markers reset when a resize can reflow lines. |
| 1337 | Inline PNG/JPEG/GIF/BMP/WebP images (the first animated frame is displayed), including bounded `MultipartFile`/`FilePart`/`FileEnd` transfers, and opt-in `inline=0` downloads to one fixed absolute directory, in the subset documented in [Terminal images](image-protocols.md); `SetMark` locations retained with scrollback and navigated by `previous_mark` / `next_mark`; `ClearScrollback` history clearing; `ClearCapturedOutput` removal of completed command-output ranges without discarding marks or prompt navigation; `HighlightCursorLine=yes/no` cursor guides; opt-in `RequestAttention=yes/once/no` platform attention hints and a 350 ms cursor-local `fireworks` burst; separately opt-in and per-pane rate-limited `StealFocus` / `Disinter` platform focus requests; opt-in, bounded and rate-limited `OpenURL=:` requests restricted to `https`, `http`, and `mailto`; opt-in one-shot `Copy=:` and unnamed `CopyToClipboard=` / `EndCopy` clipboard writes with the OSC 52 64 KiB bound; opt-in `SetBackgroundImageFile=` PNG/JPEG wallpaper replacement and clearing below a fixed read root; bounded base64 `SetBadgeFormat=` pane badges with safe `session.*` / `user.*` variable interpolation; `CurrentDir=` working-directory reports; `RemoteHost=user@host` and bounded `ShellIntegrationVersion=version;shell` pane metadata; bounded base64 `SetUserVar=name=value` metadata; `CursorShape=0/1/2`; `ReportCellSize` replies with logical height, width, and display scale; bounded `ReportVariable` queries for `session.name`, `session.terminalIconName`, `session.columns`, `session.rows`, `session.path`, `session.shell`, `session.hostname`, `session.username`, and `session.user.*` (unknown or unset variables return an empty value); and `SetColors=` for normal/bold foreground, background, cursor background/foreground, link, underline, selection foreground/background, ANSI 16-color palette, and tab using untagged, `rgb:`, `srgb:`, or `p3:` three-/six-digit colors (`tab=default` resets the tab color). `SetColors=preset=name` applies the terminal colors and ANSI palette of an exactly named registered `Toyoterm.theme` to that pane, resets earlier session color overrides, and ignores unknown names. Display P3 input is converted to sRGB for rendering. Dynamic defaults, palette entries, cursor text, hyperlinks, underlines, and selections are reflected in rendering. The bounded color stack preserves all supported session colors. Ruby-set pane badges take display precedence over OSC badges. |
| 5113 | Accept opt-in Kitty simple send and receive sessions. Send sessions support regular files, directories, symbolic links, and hard links, including parent-ID trees, bounded 4 KiB chunks, optional zlib compression, progress/final status replies, quiet modes, cancellation, safe session/file identifiers, declared-size validation, permission/mtime restoration, and a global 32 MiB in-flight bound. Completed entries remain staged until `finish`, so cancellation commits nothing. Filesystem trees are built below a private staging directory and published under a collision-safe `Transferred files` directory; external or escaping symlink targets are rejected. Receive sessions enumerate at most 64 regular files, directories, and relative non-escaping symbolic links below a separately configured fixed root, never follow symbolic links while walking, stream requested data in bounded 4 KiB chunks on the background transfer worker, optionally compress it with zlib, and reject changed or unknown paths. Each listed session is limited to 32 MiB. |
| 21337 | Set or independently clear the active pane's bounded iTerm2 session-status text, `#rrggbb` status color, and `#rrggbb` tab indicator. The active pane supplies the tab presentation; status text is rendered after the tab title and progress annotation. Unknown fields are ignored, while malformed recognized fields reject the update atomically. |

## Backlog

Priority reflects user impact, interoperability, security constraints, and
whether toyoterm has a UI/state model that can expose the result.

| Priority | OSC | Missing behavior and next step |
| --- | --- | --- |
| P2 | 1337 privileged operations | `SetProfile=name` safely aliases an exactly named registered `Toyoterm.theme`; fixed-root PNG/JPEG background images and rate-limited focus requests have separate opt-ins. Uploads (`RequestUpload`), arbitrary profile-property/key-label changes, image animation and remaining image formats, and named `rule`/`find`/`font` clipboard destinations are not supported. File, URL, or clipboard effects require explicit policy, user consent where applicable, and bounded state. |
| P2 | 5113 remaining | Transactional simple send and bounded receive sessions are supported. Add rsync delta mode while retaining the explicit fixed-root upload policy. |
| P3 | 3, 46 | X11 window-property and log-file controls are ignored; they are legacy and OSC 46 would allow untrusted output to request filesystem writes. |
| P3 | Other iTerm2 1337 metadata | Annotations, Unicode-width version stacks, and custom control sequences have no compatible consumer yet. Add individual bounded subsets only when a native or Ruby-facing use is defined. |

OSC 4/10/11/12 color queries were the first P0 gap found by this audit and are
now implemented. Unsupported OSC input is consumed without being rendered as
text.

The inventory is cross-checked against the current
[xterm control sequences](https://www.invisible-island.net/xterm/ctlseqs/ctlseqs.html),
[Kitty protocol extensions](https://sw.kovidgoyal.net/kitty/protocol-extensions/),
[iTerm2 proprietary sequences](https://iterm2.com/documentation-escape-codes.html),
and [WezTerm escape-sequence reference](https://wezterm.org/escape-sequences.html).
It intentionally distinguishes ignored legacy/private controls from missing
features that have a safe, concrete toyoterm consumer.
